# SlopBro / LG Root: review, then explicitly enabled execution

SlopBro obtains Root on **LG webOS**, installs Homebrew Channel and sets up persistence. It is not for Samsung Tizen, Android or ordinary remote control. A research request stays source-only. Only an explicit request to root an owned/authorized LG TV may select the execution phase below; skill activation, a general cleanup request or an upstream success message is not that authorization.

Read [webos.md](webos.md) for physical target binding and non-root alternatives, and [lg-source-review.md](lg-source-review.md) for provenance. Ordinary Android/LG/Tizen flows retain their no-root/no-permission-bypass boundary. This module is the sole scoped exception for the reviewed LG exploit and its declared installation/elevation/startup effects. It does not waive host permissions or authorize later system modifications, flashing, DRM changes or package purges.

## Reviewed chain and real effects

Baseline: [SlopBro 21023d56ca424607bb03d2939609cc658c655fc7](https://github.com/throwaway96/slopbro/tree/21023d56ca424607bb03d2939609cc658c655fc7); dependency: [Homebrew Channel v0.7.3, 92fcf9fef7ce08dbeae3b0616df8d0c75c11f0b3](https://github.com/webosbrew/webos-homebrew-channel/tree/92fcf9fef7ce08dbeae3b0616df8d0c75c11f0b3). Both implementations remain separate works under their own licenses; no payload is bundled by this skill.

The Python coordinator serves files, pairs over SSAP and opens a built-in WAM app. The page reaches privileged Luna/jsserver behavior, loads a fake service and invokes autoroot as Root. Autoroot changes developer state, restarts the installer, installs/elevates Homebrew and can rename an existing developer startup script. Its compatible-app selection uses the supplied major webOS version; automatic detection is disabled. Upstream reports use on webOS 4-11 and recommends a different route on some older versions. Match the complete firmware and available app evidence; a marketing year/major version alone is not eligibility.

The dependency matters: Homebrew elevation changes service/role permissions; its startup script supports user boot hooks, default unauthenticated Telnet, optional SSH, a placeholder password before SSH keys are provisioned, emergency Telnet after startup failure, and telemetry-related bind mounts. Update blocking is flag-controlled. These are part of the Root plan, not optional effects to discover after reboot. Rooting is not an atomic or fully reversible transaction.

## Execution gate: present one concrete owned-device plan

Before any pairing, listener or payload launch, establish all of the following:

1. One confirmed LG TV with stable unique identity bound to the exact private address, full model/region/firmware and supported app evidence. Recheck it with the person at the TV immediately before launch and after reconnection. No scan, guessed target, other household TV or substituted test device.
2. Physical remote/Settings access and a prepared model-specific vendor recovery route. Explain what that route can and cannot restore, including possible app/data loss and vendor intervention. Do not imply a settings snapshot is a flash backup or that uninstalling Homebrew unroots the TV.
3. Known current Root/developer state and existing startup changes. Resolve the official LG Developer Mode app conflict **before the exploit**: removing/disabling it can remove developer apps and needs its own reviewed data/recovery decision. If that conflict cannot be resolved without unapproved data loss, remain in plan mode. Do not assume Root and official Developer Mode can coexist.
4. Verified local source/assets and an audited exact Homebrew artifact/download route. The pinned autoroot can use a bundled `hbchannel.ipk`, otherwise downloads its fixed GitHub v0.7.3 asset without a digest check. Pin and review the actual bytes; use a reviewed local staging variant if a fixed dependency cannot be assured. A local variant must retain original AGPL/MIT notices, have its full diff and final hashes reviewed, and never be substituted silently or distributed under this project's MIT label. Do not use packed binaries or mixed embedded/filesystem assets whose provenance cannot be established.
5. An **already isolated, trusted TV/host network** with physical confirmation and no untrusted peers/public forwarding. SSAP TLS does not authenticate the TV server; payload delivery is HTTP; the coordinator binds all interfaces by default and `--local-ip` only changes its advertised URL. Account for every active interface/port. If adequate isolation is unavailable, stop at the plan. Never weaken host firewall, sandbox or certificate policy to proceed; no `--curl-insecure`, unauthenticated remote access on the ordinary LAN or broad account-key reuse.
6. A private session directory with user-only permissions outside the skill/upstream checkout, protected controller-key/log storage, immutable baseline evidence and an append-only journal. Record identity, source/artifact hashes, current developer/app/startup state to the extent actually readable, planned effects, unavailable baselines and recovery limits. A missing protected baseline is a risk to disclose, not permission to invent it.
7. Concrete human approval for **this** target, root/elevation/persistence, pairing/key storage, listeners, dependency installation, developer-mode conflict resolution, network/default-access handling, and any approved reboot/recovery. Host prompts/permissions remain independent. If the host requires action-time approval for privilege/access changes, honor it even when broad Root permission already exists.
8. A finite host execution deadline and cancellation mechanism, plus a recovery/observation plan for TV-side work that may outlive the coordinator. Agree on the deadline before starting (normally up to five minutes for one attempt); a timeout cannot undo an already-running payload. Do not promise automatic rollback or launch another attempt after an unknown result.

No command from this document runs automatically. A plan or source digest is not an execution token. A tool denial, uncertain firmware, unresolved startup state or absent recovery remains a stop condition even if the user permits Root generally.

## One bounded Root attempt

- Confirm the approved source and artifact bytes again, and write a durable `pending` journal entry before starting. Run as an ordinary host user, from the private session directory; the host does not need Root. Preserve argument boundaries. The upstream coordinator shape is `python3 /reviewed/slopbro/slopbro.py --asset-source dir --local-ip HOST_PRIVATE_IP --webos-version CONFIRMED_WEBOS TV_PRIVATE_IP`; substitute only validated values from the approved plan, under the host's finite timeout. This is a shape for a reviewed run, not a ready-to-paste command.
- Use the reviewed directory assets and explicit local/TV addresses/version. Do not let automatic routing choose a public/VPN interface, change the fake-service path or add debugging/telnet/insecure flags to solve an error. Pair only on the physically confirmed TV, protecting the resulting `.key` file. Do not enter any Samsung credential or use Tizen/SDB tooling here.
- Observe the TV and source logs. The coordinator's request tracker has no deadline; the host must bound it. Its “all files requested” completion is **not Root or persistence verification**. Autoroot also contains bounded installer retries; those declared internal effects belong in the plan and do not authorize an assistant retry loop.
- On failure, unexpected device text, source drift or deadline: stop further launches, close the owned host server/process, record the point reached and inspect actual TV state. The TV payload may still be running; do not kill arbitrary TV processes, replay the exploit, reboot, or restore guessed startup files. Keep isolation while recovering, and use the prepared vendor/maintainer route when state is unknown.
- Before any reboot or return to an ordinary network, use the reviewed Homebrew controls to disable normal Telnet, keep SSH disabled unless a separately approved private-key-only setup is ready, inspect existing boot hooks, leave update-blocking flags unchanged, and resolve the official Developer Mode conflict. Some controls take effect only at startup: a disabled configuration flag does not prove an already running listener has stopped. Keep isolation through any separately approved reboot and verify actual runtime access before ordinary-network use. The failsafe path can reopen emergency Telnet despite normal settings; record that residual exposure. If you cannot establish the intended access state, keep isolation and report recovery/security work pending rather than announce completion. Do not install extra root apps, arbitrary startup scripts or change stock services as part of “cleanup.”

## Verify and close

Report distinct evidence for: installed Homebrew ID/version; Root/elevation observed through the approved local UI or a separately approved read-only identity check; developer/startup state; normal remote access disabled or appropriately authenticated; and physical Home/Back/input/network/streaming health. Never equate a toast, HTTP request or UID string from an unidentified endpoint with full success.

A reboot is a separate approved check after access/startup issues are resolved. Verify the same TV and health again afterward before claiming persistence. If not tested, label persistence not tested without claiming the Root attempt failed or succeeded universally. Retain a private record of changed files/settings, unknowns, exact reviewed artifacts and recovery guidance. Uninstall is not an unroot guarantee, and a host timeout is not an inverse. Keep further customization separate and individually review every effect.
