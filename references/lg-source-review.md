## Why these projects

Home Assistant provides a maintained integration with ordinary TV controls and a documented configuration path, so an existing installation avoids writing another protocol client. aiowebostv supplies normal control/state methods and bounded connection/request waits; its reviewed client also has broad pairing permissions and transport limitations. Dev Manager offers a GUI on Windows, macOS and Linux and an active stable release with developer-app installation fixes for webOS 11. Neither its root features nor its catalog contents inherit this skill's approval.

The reviewed release is a baseline for reproducible inspection, not an instruction to downgrade a working maintained installation. Before using a different version, record its exact version, check relevant changes and review trust, pairing, endpoints, installation and recovery behavior. Use supported releases from the original publishers; do not install from floating main, blindly execute README quick starts, or change an integration's managed dependency version.

## Findings that changed the workflow

- **SSAP transport:** [aiowebostv client](https://github.com/home-assistant-libs/aiowebostv/blob/36fbc433147dd17032f63e40ada57c439625e6ed/aiowebostv/webos_client.py) tries `ws` on port 3000 before `wss` on 3001; its WebSocket call passes `ssl=False`. WSS therefore does not establish authenticated server identity. The [registration manifest](https://github.com/home-assistant-libs/aiowebostv/blob/36fbc433147dd17032f63e40ada57c439625e6ed/aiowebostv/handshake.py) requests capabilities broader than a read-only audit. Pairing must be separately authorized, keys kept private, and the route limited to a trusted private network with physical identity confirmation. The skill does not claim to narrow permissions the unmodified library requests.
- **SSH server trust:** Dev Manager uses [ares-cli-rs connection setup](https://github.com/webosbrew/ares-cli-rs/blob/ef1247bc5b2fc4cdc625b663eb7721e8242d80b6/common/connection/src/session.rs), which disables known-hosts storage and retains legacy algorithms. Do not claim the GUI enforces a recorded host-key pin, add global legacy SSH settings, or treat possession of a client key as proof of the server's identity. Apply the private-network/physical-confirmation gate or remain in plan mode when policy requires authenticated transport.
- **Developer-session effects:** [LG's official guide](https://webostv.developer.lge.com/develop/getting-started/developer-mode-app) describes activation reboot, key acquisition, session extension and removal of developer apps after disable/expiry. This is an app lifecycle with data-loss considerations. Disabling developer mode and clearing its all-app cache are not generic rollback steps.
- **No universal power semantics:** Home Assistant documents a separate Wake-on-LAN/CEC route for power-on and model-dependent screen-only control. A reported [heartbeat failure](https://github.com/home-assistant/core/issues/181890) can temporarily misrepresent an on TV as off; [screen control reports](https://github.com/home-assistant/core/issues/183602) also show firmware differences. These issue reports are evidence of failure modes, not permission to install suggested patches or send undocumented service requests.
- **Permission errors are boundaries:** A denied or unavailable service may reflect firmware or granted scope. Do not restore an old signed manifest, forge credentials, install a patched client, retry privileged URIs, or root the TV to make an ordinary feature work. Record unsupported actions and offer the physical remote.
- **SlopBro changes system trust:** The coordinator, main payload and autoroot script establish a root/elevation/persistence chain; unbounded request tracking and external downloads do not yield an execution/recovery guarantee. Details belong only in [slopbro-research.md](slopbro-research.md).

## Source and license handling

These are independent workflow instructions and source-review notes, not a redistribution of the clients or exploit. No upstream webOS code, pairing manifest, binary, IPK, test key, payload or screenshot is included. Install optional tools separately under their own terms. Preserve source references in [NOTICE](../NOTICE). Copying or deriving implementation would require a separate license review; in particular, a separate folder does not remove AGPL obligations.
